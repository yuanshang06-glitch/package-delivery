# 成果完整交付

版本：1.3.0（开发候选）。数据格式沿用collaborator-delivery/1及collaborator-traceability/1；需要GB级工程/资料交付时读[大文件交付](references/large-files.md)。

音视频成果交付时读[媒体交付扩展](references/media-delivery.md)：声明主视频/音频及字幕、转写、源文件等配套内容，使用可选本地ffprobe生成技术检查报告。缺工具或信息未知明确not_run；基础ZIP检查不判断媒体可播放性、画质、听感或字幕同步。接收方在解压目录独立复核；任务书要求的必需检查未运行或失败时，将交付标为partial/blocked并列缺口。

让收件人只拿到这个包，就知道交付了什么、如何使用、哪些验证做过、还缺什么及下一步由谁处理。打包只覆盖已授权任务，不附带上传、发消息、部署或修改其他项目的权限。

## 接任务时

沿用已有任务书的目标、读写范围、交付物、验收标准、环境及禁止动作。只问影响交付的缺项；缺账号/设备/服务时记录阻塞，不虚构完成。

派任务可填写[任务单模板](references/task-brief.md)，或附上这句（任务目标和验收标准仍须另给）：

> 请按 package-delivery 的 SKILL.md 完成交付。只打包本任务范围内的成果，包含可读入口、实际产物、验证证据、未完成项和ZIP；自测不代替接收方验收。

## 完工时

在独立staging目录准备：

- `START-HERE.md`：成果和使用入口、最少接手步骤、环境/依赖、实际验证、已知限制、未完成项和后续动作。路径按**解压后的最终布局**写，不引用作者电脑或临时工作区；输入快照目录不是最终安装位置。
- `artifacts/`：最终产物。代码交源码、必要配置模板和运行/测试入口；文档交最终文档及任务要求的可编辑源文件。小改动可交受影响文件/patch，加明确基线和应用步骤，不必复制整仓库。
- `evidence/`：支撑结论的真实检查、命令/退出码、必要截图或样本。说明来源，旧证据不能写成本次重跑。没跑就写没跑和原因；不要编造日志。
- `DELIVERY.json`：按[交付格式](references/delivery-format.md)填状态、文件白名单、检查、未完成项和接手动作。完成/部分完成/阻塞都可交付；当前交付候选独立接受为`UNKNOWN`，接收方另行评审。

核对源码、相对引用和资源齐全。依赖过大或需联网时给版本/获取步骤及未离线验证的限制。沿用任务指定格式，不为打包改变产品或悄悄修额外问题。

普通模式默认单文件64MiB/总128MiB。明确的大文件任务可选择large（单文件8GiB/总16GiB），双方命令都要显式加--profile large；接手说明给出容量、磁盘空间、模式与实际测试边界。已压缩工程资源可用--compression stored，避免重复压缩。大型payload仍逐块校验，不取消目录和小元数据限额；不要因包内声称需要large而自动提高接收预算。

按[可追溯扩展](references/traceability.md)在DELIVERY.json补充traceability：每条任务验收要求对应产物、验证记录与缺口；验证记录注明命令、相对工作目录、环境、退出码、本次执行/继承/未运行，并绑定被验证产物的SHA-256。要求与证据类型由执行者如实填写，脚本只核对一致性。不能用测试数量替代逐条需求核对。

返修还要记录上一包SHA-256、解决哪条反馈、实际改了什么及本轮验证；旧包保留。接手说明给出简洁的“要求—产物—证据—缺口”表，细节仍以结构化记录为准。

不要整目录盲打包。明确排除凭据、真实环境密钥、无关私有资料、个人记忆、其他会话原文、缓存和可再生依赖。无秘密的配置模板可以交付。摘要不能证明作者身份或内容没有秘密，仍需核对文件范围。

## 打包与复核

需要ZIP时用本skill自带Python 3标准库脚本，无需安装依赖：

```text
python /path/to/package-delivery/scripts/delivery.py pack --root /path/to/staging --out /path/to/new-delivery.zip
python /path/to/package-delivery/scripts/delivery.py verify /path/to/new-delivery.zip
python /path/to/package-delivery/scripts/check_handoff.py /path/to/new-delivery.zip
```

实际路径以skill所在位置为准。脚本只读DELIVERY.json白名单，生成MANIFEST.json覆盖元数据和全部声明文件（不循环给自己做摘要），不扫描项目。

打包、完整性与可追溯检查均退出0后才交含可追溯扩展的ZIP。独立解压或从ZIP重读入口，按最终布局核对链接、源码/资源和接手命令。验证与任务风险匹配：文档核对正文和引用，代码运行有意义的既有检查，不用无关测试凑数量。旧v1包可只跑完整性验证，明确没有通过v1.1可追溯检查。

最终ZIP的校验结果和包摘要放交付消息或包外回执；包内evidence记录打包前的实际检查。不要为了把ZIP自身摘要塞回包而反复改包，也不能用旧包的验证记录冒充当前包。

未要求ZIP或环境无Python，可交同结构文件夹并明确未执行脚本校验；不能声称ZIP已验证。工具失败要说明原因，半成品不能报完整成功。

交付消息给：包的位置、成果概要、实际检查、未完成/阻塞及接手第一步。打包成功和worker completed均不是接收方ACCEPTED。返修保留旧包，生成新版本或attempt。
